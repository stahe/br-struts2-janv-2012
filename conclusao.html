    21. Conclusão

    Nas linhas 12, 14 e 16, são relatados erros graves. Dois deles indicam uma possível fuga de memória. De fato, o aplicativo [pam-02] apresenta fugas de memória. Após algum tempo, o aplicativo fica inutilizável. É necessário, então, fechar o NetBeans e reimplantar o aplicativo.

    Todos os erros se referem a threads. A aplicação [pam-02] não utiliza threads por conta própria. Portanto, deve-se suspeitar dos frameworks utilizados: Struts 2, Spring 2.5 e Tiles. É possível excluir razoavelmente o Tiles, que provavelmente não gerencia threads. Restam o Struts e o Spring.

    Fazemos então outro teste:

    Implementamos a camada [web] com o framework JSF em vez do Struts 2. Nada mais muda. Recebemos, então, as mesmas mensagens de erro que com o Struts 2.

    Portanto, o culpado parece ser o Spring, o pool de conexões dbcp usado aqui pelo Spring, ou até mesmo eu, caso não tenha utilizado o Spring corretamente. Posso ter esquecido uma configuração do Spring que permitiria limpar os threads criados, posso ter... A solução para esse problema de vazamento de memória ainda precisa ser encontrada.

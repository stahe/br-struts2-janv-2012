    3. Exemplo 02 – Injeção de parâmetros na ação

    3.1. O projeto NetBeans

    • em [1,2], os arquivos de configuração
    • em [3], a ação
    • em [4], a visualização
    • em [5], as bibliotecas do projeto

    3.2. Os arquivos de configuração

    O arquivo [web.xml] é o seguinte:

    
<?xml version="1.0" encoding="UTF-8"?>

<web-app xmlns="http://java.sun.com/xml/ns/javaee"
     xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
     xsi:schemaLocation="http://java.sun.com/xml/ns/javaee http://java.sun.com/xml/ns/javaee/web-app_3_0.xsd"
     version="3.0">
 
  <display-name>Struts tuto-001</display-name>
  <filter>
    <filter-name>struts2</filter-name>
    <filter-class>org.apache.struts2.dispatcher.FilterDispatcher</filter-class>
  </filter>
  <filter-mapping>
    <filter-name>struts2</filter-name>
    <URL-pattern>/*</URL-pattern>
  </filter-mapping>
  <session-config>
    <session-timeout>
            30
    </session-timeout>
  </session-config>
</web-app>

    Já comentamos esse arquivo. Não faremos isso novamente. Basta lembrar que ele garante que todos os URL (linha 15) sejam submetidos ao filtro do Struts (linha 10).

    O arquivo [struts.xml] é o seguinte:

    
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE struts PUBLIC
        "-//Apache Software Foundation//DTD Struts Configuration 2.0//EN"
        "http://struts.apache.org/dtds/struts-2.0.dtd">

<struts>
 <package name="default" namespace="/" extends="struts-default">
    <default-action-ref name="index" />
    <action name="index">
      <result type="redirectAction">
        <param name="actionName">Action1</param>
        <param name="namespace">/actions</param>
      </result>
    </action>
  </package>
  <package name="actions" namespace="/actions" extends="struts-default">
    <action name="Action1" class="actions.Action1">
      <result name="success">/vues/Action1.JSP</result>
    </action>
  </package>
</struts>
    • linhas 7-15: definem o pacote [default], que é utilizado quando uma ação não foi encontrada em outro pacote.
    • linha 8: define uma ação padrão para esse pacote, chamada index.
    • linhas 9-14: configuram a ação denominada index. Observa-se que ela não está associada a uma classe (ausência do atributo class na linha 9).
    • linha 10: o resultado é para a chave success (ausência do atributo name). É do tipo redirectAction (atributo type). Esse tipo permite redirecionar uma ação para outra ação. Aqui, quando o cliente solicitar a ação /index, ele será redirecionado para a ação /actions/Action1 (linhas 11-12).
    • linhas 16-20: definem o pacote de ações (name) associado às ações URL e /actions/Action (class).
    • linhas 17-19: configuram a ação /actions/Action1 (name). Quando essa ação for solicitada, o Struts instanciará a classe actions.Action1 (class) e, em seguida, o método execute dessa classe será executado. Este método deverá retornar a chave success, pois é a única chave definida na linha 18.
    • linha 18: para a chave success, a visualização a ser exibida será a página JSP [vues/Action1.JSP].

    Concluindo, observamos que o projeto Struts só consegue executar a ação de URL [actions/Action1].

    3.3. L'action

    A ação Action1 é representada pela seguinte classe:

    
package actions;

import com.opensymphony.xwork2.ActionSupport;

public class Action1 extends ActionSupport{
  
  // modelo da ação
  private String param1="valeur1";
  private String param2="valeur2";
  
  @Override
  public String execute(){
    return SUCCESS;
  }
  
  // getters e setters

  public String getParam1() {
    return param1;
  }

  public void setParam1(String param1) {
    this.param1 = param1;
  }

  public String getParam2() {
    return param2;
  }

  public void setParam2(String param2) {
    this.param2 = param2;
  }
  
}
    • linhas 8-9: dois campos acessíveis por meio de get/set (linhas 18-32)
    • linhas 12-14: o método execute retorna a chave success, conforme esperado. Ele não faz mais nada.

    3.4. A visão JSP

    A visão Action1.JSP é a seguinte:

    
<%@page contentType="text/html" pageEncoding="UTF-8"%>
<%@ taglib prefix="s" uri="/struts-tags" %>
<!DOCTYPE html>
<html>
  <head>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
    <title>Action1</title>
  </head>
  <body>
    <h1>Action1</h1>
    param1=<s:property value="param1"/><br/>
    param2=<s:property value="param2"/><br/>
  </body>
</html>

    Essa visualização é exibida após a execução do método [Action1].execute. Ela exibe os valores dos campos param1 (linha 11) e param2 (linha 19) da classe [Action1].

    3.5. Os testes

    Vamos executar o projeto [exemple-02]:

    • em [1], o URL solicitado. Observe que o URL inicial solicitado era [/exemple-02], sem ação. Os arquivos [web.xml] e [struts.xml] foram então explorados. Verificou-se que o arquivo [web.xml] delegava o processamento de todas as solicitações ao Struts 2. O arquivo [struts.xml] foi então explorado: 
    
<struts>
 <package name="default" namespace="/" extends="struts-default">
    <default-action-ref name="index" />
    <action name="index">
      <result type="redirectAction">
        <param name="actionName">Action1</param>
        <param name="namespace">/actions</param>
      </result>
    </action>
  </package>
  <package name="actions" namespace="/actions" extends="struts-default">
    <action name="Action1" class="actions.Action1">
      <result name="success">/vues/Action1.JSP</result>
    </action>
  </package>
</struts>

    O URL, sem ação, foi processado pelo pacote default nas linhas 2 a 10. Na ausência de ação no URL, a ação passou a ser index devido à linha 3 (ação padrão). As linhas 4 a 8 fizeram com que o Struts retornasse ao cliente um URL de redirecionamento para [/exemple-02/actions/Action1], conforme exibido no [1].

    A ação [Action1] foi então executada conforme configurado nas linhas 12 a 14. Seu método execute foi executado. Vimos que ela retornou o código success. A linha 13 de [struts.xml] fez com que a página [/vues/Action1.JSP] fosse retornada ao navegador:

    
...
<html>
  <head>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
    <title>Action1</title>
  </head>
  <body>
    <h1>Action1</h1>
    param1=<s:property value="param1"/><br/>
    param2=<s:property value="param2"/><br/>
  </body>
</html>

    As linhas 9 e 10 exibiram os valores dos campos param1 e param2 de [Action1]. É isso que mostra [2].

    Vamos solicitar outro URL:

    No [1], a ação [Action1] é solicitada com os parâmetros param1 e param2. Voltemos ao esquema de execução de uma ação Struts:

    O controlador [FilterDispatcher] faz com que o método execute da ação seja executado. O fluxo de execução passa por interceptadores. Um deles processa a cadeia de parâmetros param1=qqchose&param2=autrechose. Em seguida, ele utiliza os métodos setParam1 e setParam2 da ação Action1:

    
package actions;

import com.opensymphony.xwork2.ActionSupport;

public class Action1 extends ActionSupport{
  
  // modelo da ação
  private String param1="valeur1";
  private String param2="valeur2";
  
  @Override
  public String execute(){
    return SUCCESS;
  }
  
  // getters e setters

  public String getParam1() {
    return param1;
  }

  public void setParam1(String param1) {
    this.param1 = param1;
  }

  public String getParam2() {
    return param2;
  }

  public void setParam2(String param2) {
    this.param2 = param2;
  }
  
}

    O interceptador params executa os seguintes métodos:

    [Action1].setParam1("qqchose") ;
[Action1].setParam2("autrechose") ;

    Portanto, eles precisam existir. É importante observar o seguinte: para recuperar os parâmetros parami de uma solicitação HTTP, é necessário que a ação Struts chamada possua campos com os mesmos nomes dos parâmetros e métodos get/set associados.

    Quando o método execute de [Action1] é executado, os campos param1 e param2 foram inicializados pelo interceptador *params:*

    param1="qqchose"
param2="autrechose"

    O método execute retorna a chave success e a página [Action1.JSP] éexibida com os novos valores de param1, param2 e [2].
